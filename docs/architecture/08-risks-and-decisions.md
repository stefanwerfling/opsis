# 08 – Risiken und offene Entscheidungen

## Technische Risiken

| #   | Risiko                                                                                                                                                                | Gegenmaßnahme                                                                                                                                                           |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | **MCP-SDK v2 ist jung** (v2 seit 04/2026, Spec 2026-07-28). Die API kann sich in Minor-Versionen noch ändern, Clients sprechen teils noch 2025-er Protokollversionen. | Version exakt pinnen. MCP-Code in `server/src/mcp` kapseln. Integrationstests mit dem offiziellen Client in beiden Protokollversionen.                                  |
| R2  | **Client-seitige Tool-Timeouts** begrenzen `wait_for_specification` (je nach Client 60 s bis einige Minuten).                                                         | Standard-Timeout 120 s, Progress-Notifications, idempotente Wiederaufnahme. Die Dokumentation empfiehlt eine Agentenschleife.                                           |
| R3  | **EventBus nur im Prozess.** Mehrere Serverinstanzen würden Ereignisse verpassen.                                                                                     | Ein Prozess als unterstützte Betriebsform. Der DB-Poll im Wartevorgang sorgt trotzdem für korrekte Ergebnisse. Später ist ein Postgres-`LISTEN/NOTIFY`-Adapter möglich. |
| R4  | **TypeScript 7** ist `latest`, wird aber noch nicht von typescript-eslint unterstützt.                                                                                | TS 6.0 pinnen, Upgrade als eigener Schritt.                                                                                                                             |
| R5  | `node:sqlite` hat in Node 24 den Stabilitätsgrad „Release Candidate“.                                                                                                 | Zugriff nur über die Repositories in `server/src/infrastructure/db`. Ein Wechsel zu `better-sqlite3` (fast identische synchrone API) bliebe lokal.                      |
| R6  | **Große Screenshots** (z. B. 1440×12000 Full-Page) belasten Browser und Canvas.                                                                                       | Kachel- bzw. Thumbnail-Stufen per `sharp`. Canvas lädt eine Vorschau und schaltet ab Zoomstufe X auf das Original um. Limits aus 01 §6.                                 |
| R7  | **Base64-Bilder in Tool-Argumenten** vergrößern Payload und Kontext des Agenten.                                                                                      | Limit + `request_upload`-Weg. Bild-Inhalte werden in Antworten nur auf Wunsch zurückgegeben.                                                                            |
| R8  | **Regelbasierte Konflikterkennung** kann falsch-positive Treffer liefern.                                                                                             | Regeln liefern nur Hinweise, der Mensch entscheidet. Jede Regel ist einzeln getestet.                                                                                   |
| R9  | Unbegrenzt wachsende History (Blobs).                                                                                                                                 | Inhaltsadressierung dedupliziert. Ein Aufräumjob entfernt nur Blobs ohne Referenz. Kein Löschen historischer Daten ohne explizite Funktion (E7).                        |

## Offene fachliche Entscheidungen (bitte bestätigen oder korrigieren)

Für jede Entscheidung ist ein Vorschlag als Default eingetragen. Ohne Bestätigung wird er
**nicht** als verbindliche Anforderung, sondern als konfigurierbarer bzw. leicht
änderbarer Default umgesetzt.

| #   | Frage                                                                                                                                        | Vorschlag                                                                                                                                                                                                                                   |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E1  | **Menschliche Benutzer:** Einzelplatz (lokal, ohne Login) oder Mehrbenutzer mit Konten und Rollen?                                           | **Entschieden (2026-11-07): Einzelplatz**, lokal auf `127.0.0.1`, ohne Login. Das Akteursmodell (`human:<id>`) bleibt für Mehrbenutzer offen.                                                                                               |
| E2  | **Betriebsform:** nur lokal pro Entwickler oder zentral im Team bzw. Netzwerk mit entfernten Agenten?                                        | lokal zuerst. Netzwerkbetrieb über Konfiguration mit Token-Pflicht und TLS über einen Reverse Proxy.                                                                                                                                        |
| E3  | **„delivered“:** Gilt eine Session als ausgeliefert, sobald der Agent den Prompt abruft, oder erst nach einer Bestätigung durch den Agenten? | **Entschieden (2026-11-07): beim ersten Abruf des Prompts.** Weitere Abrufe liefern dieselbe PromptVersion. Danach ist keine Wiedereröffnung mehr möglich, Änderungen laufen über eine neue Überarbeitungs-Session.                         |
| E4  | **Tool-Namen** `opsis.xyz` (wie in der Anforderung) oder `opsis_xyz` (kompatibel mit allen Clients)?                                         | **Entschieden (2026-11-07): `opsis_xyz`**                                                                                                                                                                                                   |
| E5  | Zusätzlich ein **stdio-Proxy** für Clients ohne HTTP-Unterstützung?                                                                          | später, bei Bedarf                                                                                                                                                                                                                          |
| E6  | **Import-Konflikte** (ID existiert bereits): neue IDs vergeben oder Import ablehnen?                                                         | neue IDs + Mapping-Protokoll                                                                                                                                                                                                                |
| E7  | Dürfen Projekte bzw. historische Daten jemals **gelöscht** werden (z. B. DSGVO, Platz)?                                                      | nur Archivieren. Endgültiges Löschen eines ganzen Projekts als explizite Admin-Funktion.                                                                                                                                                    |
| E8  | **Sprache** von UI und generiertem Prompt: Deutsch, Englisch, wählbar?                                                                       | **Entschieden (2026-11-07):** UI zweisprachig en/de (i18n von Anfang an, Standard aus der Browsersprache). Das Prompt-Gerüst ist pro Projekt en/de wählbar, Standard `en`. Benutzertexte werden nie übersetzt, sondern wörtlich übernommen. |
| E9  | Soll OPSIS **eigene automatische Vorschläge** machen (z. B. Komponenten erkennen per Bildanalyse oder LLM)?                                  | revidiert (2026-11): **Vorschläge durch den verbundenen MCP-Agenten** (`opsis_propose_components`), nur vor Beginn der Prüfung. Alle Werte sind `auto_detected` und müssen bestätigt werden. OPSIS selbst ruft kein LLM auf.                |
| E10 | Lizenz bleibt **MIT**?                                                                                                                       | ja (bestehende LICENSE)                                                                                                                                                                                                                     |
